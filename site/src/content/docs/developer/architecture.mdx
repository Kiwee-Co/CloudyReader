Cloudy Reader is a Python 3.12 package with a Qt window. One call, `Pipeline.prepare`, turns a paste into a `Reading`: the spoken script and a WAV file. Every stage is injected, so a test can swap any stage for a fake.

`Pipeline.prepare(raw, voice_key, opts)` runs these steps in order:

1. **Guard.** Blank text raises `ValueError("nothing to read")`. The voice is looked up first, so a wrong key fails before any lookup. A voice that is not installed raises `ValueError` with the reason that its row shows.
2. **Parse.** `QuestionParser.parse` returns `Question` objects. It also takes bracket guides out of the stem and the choices and keeps them as `Respelling` objects. No question raises `ValueError("nothing to read")`.
3. **Detect.** `SciEntityDetector.detect` scans each stem and each choice. It scans the answer only when `read_answer` is on. It returns `EntitySpan` objects.
4. **Resolve.** `ChainResolver.resolve_many` looks up the first span of each unique text within `lookup_budget_s`. The pipeline uses the online resolver when `opts.online_lookups` is true and `settings.offline` is false. Otherwise it uses the offline twin: cache and OPSIN only.
5. **Normalize.** `ScriptNormalizer.to_script` builds a `SpokenScript`: segments, pauses, pronunciation overrides, and warnings. It makes one segment each for the header, the category, the format, the stem, and the answer. A choice makes two segments: its letter and its text. The letter segment carries its own pause, so the inserted silence does not depend on how a voice reads the period.
6. **Synthesize.** `TtsService.synthesize` returns an `Audio` from the WAV cache or from a voice engine.
7. **Collect notes.** The pipeline merges three lists: the normalizer warnings, the engine warnings from the last synthesis, and the engine's pre-check of the script. It removes duplicates and returns the `Reading`.

Detection, resolution, and the engine pre-check only refine the speech. If one fails, `_best_effort` logs a warning and adds the note `<stage> failed (<ErrorType>); continuing without it`. The reading goes on.

Before a reading, the window asks `Pipeline.load_hint(voice_key)`. Chatterbox Turbo and Qwen3-TTS answer with a status text until their model loads, and the window adds that text to the status of the reading. Piper, Kokoro, and the macOS engine define no hint, so they answer `None`, and so does a voice that is not ready.

### Keep rule R5

The code states rule R5 in several modules: a resolution decides how a token is said, never which token is said. The pipeline hands resolutions to the normalizer only. It never reads a resolved name and never edits the questions or the script. The lexicon, the formula stage, and the normalizer follow the same rule.

## Data contracts

`models.py` defines these types:

| Type            | Holds                                                                                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Question`      | Kind, number, category, format, stem, choices, answer, raw text, and the guides found in the stem.                                                               |
| `Choice`        | A letter (`W`, `X`, `Y`, or `Z`), its text, and the guides found in the text.                                                                                    |
| `Respelling`    | A guide: the printed `surface`, the guide text, and a `kind` of `phonetic`, `spoken`, or `spell`.                                                                |
| `EntitySpan`    | A detected name: offsets, text, a label, and a source of `ner` or `regex`.                                                                                       |
| `Resolution`    | The answer to a lookup: query, kind, canonical name, ids, source, and a status of `ok`, `not_found`, `timeout`, `offline`, or `error`.                           |
| `Override`      | An exact pronunciation: a `surface`, neutral General American IPA, and a source of `respelling`, `lexicon`, or `iupac`.                                          |
| `Segment`       | Text, a pause after it in milliseconds, and its overrides.                                                                                                       |
| `SpokenScript`  | Segments and warnings. `text()` joins the segment text.                                                                                                          |
| `VoiceInfo`     | Key, engine, name, language, quality, speaker count, installed flag, path, the reason a voice is not installed, and the precision that the **Voice** menu shows. |
| `RenderOptions` | `read_answer`, `speed`, `online_lookups`, and `speaker_id`.                                                                                                      |
| `Audio`         | The WAV path, sample rate, duration, and a cache-hit flag.                                                                                                       |
| `Reading`       | Questions, script, entities, resolutions, audio, and warnings.                                                                                                   |

The protocols `Parser`, `EntityDetector`, `Resolver`, `Normalizer`, `TtsEngine`, `AudioPlayer`, and `ReaderService` describe what each part needs from the others.

`TtsService` also uses these optional parts of an engine when it has them. They are `version` and `voice_version(voice)` for the cache key, `placeholder_voices()` for dimmed rows, `load_hint()`, `script_warnings(script, voice)`, `last_warnings`, and `unavailable_reason`.

## How pronunciation reaches the voice

An `Override` carries neutral IPA. The stress mark sits before the stressed syllable. There are no length marks. A stressed NURSE vowel is `ɜɹ`. Each engine either converts the IPA or says the word from a spelling.

- **Piper.** `to_piper_layout` moves stress marks to the espeak layout and adds the long vowels. `_usable_ipa` keeps only symbols in the voice's phoneme map and warns about the rest. The engine swaps each whole-word surface for an inline `[[ipa]]` block, longest surface first. Sentence marks move inside the block, because Piper drops punctuation after a block.
- **Kokoro.** `ipa_to_misaki` maps the IPA to the phoneme alphabet of Kokoro-82M. The engine marks each surface as `[surface](/phonemes/)`. A symbol outside the model vocabulary is rejected with a warning.
- **Chatterbox Turbo and Qwen3-TTS.** Neither engine takes IPA. `speakable` in `mlxkit.py` says a respelled word from its respelling, in lower case with its hyphens kept. It says a lexicon word or a checked chemical name as printed. The engine adds one warning that counts those words and names the first three. Chatterbox Turbo also drops square brackets from the text, because its tokenizer reads them as sound cues. A lone choice letter is the exception: `engines/letter_clips.py` plays a recorded clip for Ryan, Aiden, and the Chatterbox Turbo voice. Only a clip that is missing, or fails its checks (the SHA-256 value, the format, or the manifest values), sends the letter to the model, and `say_letter` in `mlxkit.py` then respells it: `double you.` for W, `ecks.` for X, and `Why.` for Y. Z stays `Z.`
- **macOS.** The `say` program takes no IPA. The engine calls `speakable` with the `hyphen` style. It says a respelled word from its lower-case respelling, and a lexicon word or a checked chemical name as printed. It adds one warning that counts those words and names the first three. It also turns `[[` and `]]` in the text into single brackets, so pasted text cannot run a `say` command.

## Engines

Piper and Kokoro take IPA. They differ in these ways:

| Aspect         | Piper                                                      | Kokoro                                                                                  |
| -------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Class          | `PiperEngine`                                              | `KokoroEngine`                                                                          |
| `available()`  | The `piper` package is installed.                          | Apple silicon, backend packages present, and model files with the pinned SHA-256 value. |
| `voices()`     | Every `.onnx` plus `.onnx.json` pair in the voices folder. | Each voice in the pinned voice list, with its published grade.                          |
| Output         | 16-bit mono WAV at the voice's sample rate.                | 16-bit mono WAV at 24,000 Hz.                                                           |
| Version string | `piper-tts-<version>+r<render revision>`                   | `kokoro-82m@<revision>+misaki-ipa-2+r1`                                                 |

Piper, Kokoro, and the two optional engines write the pause after a segment as exact silence in the WAV file. That silence does not depend on the voice. The macOS engine writes each pause into the text as `[[slnc ms]]`, and `say` makes the silence.

A voice can add its own silence around a line. Piper and Kokoro call `trim_letter_padding` in `engines/padding.py` to cut that silence next to a choice letter. The two optional engines and the macOS engine do not call it.

`TtsService.voices()` sets the order of the **Voice** menu. Engines follow `ENGINE_ORDER` in `voice_meta.py`: Kokoro, Chatterbox Turbo, Qwen3-TTS, Piper, then macOS. Inside an engine, the best grade or tier comes first, an ungraded voice comes last, and a tie goes by name. An engine that is not available lists the dimmed rows of its `placeholder_voices()`, when it has that method.

The voice picker selects the first installed voice when no saved voice applies.

The menu shows one label for each voice, built by `voice_label` in `voice_meta.py`. A label joins the name, the accent and gender where known, the engine, and the precision. It reads `Lessac (US, female) · Piper · medium`. A voice that is not installed adds `—` and its reason, and the tooltip of the row holds the whole reason. The tooltip of a Kokoro row names its published grade. `spoken_label` writes the same facts for VoiceOver, and `unique_labels` adds the voice id in brackets when two labels match.

`build_default_service` always registers Piper. It registers Kokoro only when `platform.machine()` is `arm64` and the module imports. Then `_optional_engines` imports each module of `_OPTIONAL_ENGINES`, on Apple silicon only. A module that is missing or broken is skipped with a log line, so the other engines still work. It registers `MacosEngine` last, on every platform: off macOS the engine reports itself unavailable and lists no voice. Bump `_RENDER_REVISION` in the module of an engine, or the `+r` suffix of `KokoroEngine.version`, when rendering changes, so old cached WAV files stop matching.

### Optional engines

`chatterbox_turbo` and `qwen3_tts` take plain text, not IPA. They share `engines/mlxkit.py`, and they differ in these ways:

| Aspect         | Chatterbox Turbo                                                                     | Qwen3-TTS                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| Class          | `ChatterboxTurboEngine`                                                              | `Qwen3TtsEngine`                                                                                          |
| Voices         | One built-in voice, key `chatterbox_turbo:builtin`.                                  | Two presets, keys `qwen3_tts:ryan` and `qwen3_tts:aiden`.                                                 |
| `available()`  | The catalog says `ready`, and no file damage is on record.                           | The catalog says `ready`, the decoder gate is open, and no refusal or damage is on record.                |
| Chunk limit    | 280 characters                                                                       | 300 characters                                                                                            |
| Version string | `chatterbox-turbo-4bit@<revision>+mlx-audio-<version>+<sampling>+r<render revision>` | `qwen3-tts-0.6b-customvoice-8bit@<revision>+mlx-audio-<version>+<sampling>+dec-<mode>+r<render revision>` |

Both engines write 16-bit mono WAV at 24,000 Hz. In a version string, `<revision>` is the first 8 characters of the pinned commit, or `norev` when none is pinned. `<sampling>` is the sampling tag, such as `t0.8k1000p0.95r1.2`. `<mode>` is the mode of the decoder gate.

- **Catalog.** `engine_catalog.py` holds `SPECS`: the repository, voices, license, credit, and expected files of each engine. `assess` returns one of `ready`, `missing`, `blocked`, or `broken`, with the reason to show. It checks these in order: the hard reason from the `supported()` of the module, the pins in the lock, the `gate()` of the module, damage, missing files, offline mode, and room to write. An engine with a hard reason or no pinned file has no row. Any other engine that is not ready shows dimmed rows from `placeholder_voices()`, and `VoiceInfo.reason` says why.
- **Files.** `ModelFiles` in `mlxkit.py` checks the pinned files. `assess` uses `stat` only. A symlink, a pickle-capable file, an unpinned `.safetensors` file, a path that is not a file, or a wrong size marks the folder damaged. Before the first load, the engine hashes each pinned file once for each file state. A mismatch marks the folder damaged until a file changes.
- **Text.** `speakable` turns each segment into text. A lone choice letter goes no further while its clip plays: only a missing clip, or one that fails its checks, lets the letter reach the steps below. `chunk_text` cuts the text at sentence ends, then clause ends, then spaces. `render_text` renders each chunk. A chunk under 24 characters, such as a single hard word, gets two tries. Then it gets one call with three copies of the text, and the engine crops the first copy. A longer chunk gets three tries. The engine puts 120 ms of silence between chunks and writes each pause as exact silence. Seeds come from the voice, the text, and the try number, so the same reading sounds the same. A script over `MAX_SCRIPT_CHARS` raises `EngineError`.
- **Offline.** `offline_guard` sets `HF_HUB_OFFLINE` and `TRANSFORMERS_OFFLINE` for a load, and it swaps the Hugging Face download functions for stubs that raise. A load never reaches the network.
- **Model slot.** The two engines share `SLOT`, a `ModelSlot`. It limits how many engine models stay loaded and unloads the oldest first, so switching engines can reload a model. Kokoro is outside it.
- **Decoder gate.** `qwen3_tts` needs a fix for a decoder bug in `mlx_audio`. `decoder_gate` picks `upstream` when the fix is present, `patch` for the audited file that has the bug, and `blocked` for anything else. A blocked gate gives dimmed rows and no download. With `patch`, the engine patches the decoder before it loads the model, and `window_probe` must pass first.

### macOS engine

`MacosEngine` in `engines/macos.py` reads with the voices that macOS has installed. It needs no download and no model file, so it has no pinned file in `assets.lock.json` and no entry in `SPECS` of `engine_catalog.py`. It differs from the other engines in these ways:

| Aspect         | macOS                                                                                                           |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| Class          | `MacosEngine`                                                                                                   |
| `available()`  | The platform is macOS, and `/usr/bin/say` is executable.                                                        |
| `voices()`     | The English voices that `say --voice=?` prints, minus 15 novelty voices. The listing runs once for each launch. |
| Precision      | The tier in the listed name, `Premium` or `Enhanced`. Any other voice is `Standard`.                            |
| Output         | 16-bit mono WAV at 24,000 Hz.                                                                                   |
| Version string | `macos-say@<macOS version>+r<render revision>`                                                                  |

- **Run.** One `say` run reads the whole script. The text goes in on standard input, and `say` writes the WAV file to a private temporary folder that the engine deletes after the reading. The engine passes an argument list, never a shell command, and the environment `PATH=/usr/bin:/bin`.
- **Time budget.** The engine kills a run that lasts longer than 30 seconds plus 0.01 second for each character. The reading then fails with an `EngineError`.
- **Speed.** At speed 1.0, `say` keeps the voice's own rate. Another speed becomes `--rate` with `round(175 * speed)`. The engine clamps a speed to 0.5 through 2.0 and adds a warning when it does.
- **Speaker.** Each macOS voice has one speaker. The engine ignores a speaker number and adds a warning.

## WAV cache

`TtsService` keeps one WAV per distinct request in `cache/wav`. The file name is the SHA-256 value of a JSON object. The object holds the segments with their pauses and overrides, the voice key, the speed, the speaker, and the engine version. An engine that defines `voice_version` adds that value to the version. For Piper it is a fingerprint of the voice files, so a replaced voice renders again. For an optional engine it is the voice id and a fingerprint of the pinned files. The macOS engine defines none, and its version string carries the macOS version, so an update of macOS renders again. Options that only shape the script are not in the key.

A change to the segments, including a pause length, changes the file name. The app then renders the question again.

On a miss, the service writes to a temporary file in the same folder. Then it moves the file into place with `os.replace`. A reader never sees a half-written file. Nothing prunes the folder.

## Threads

The app uses these threads:

| Thread                  | Started by                                          | Work                                                                                                                |
| ----------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| UI thread               | Qt                                                  | The window, the signals, a 150 ms poll that detects the end of playback, and the 150 ms timer of the live preview.  |
| One worker              | `MainWindow`, a `QThreadPool` limited to one thread | `service.voices()`, `service.prepare(...)`, and the live preview `service.preview_script(...)`, one call at a time. |
| `cloudyreader-prefetch` | `MainWindow._start_prefetch`                        | `VoicePrefetch.run`. A daemon thread that reports by queued signals.                                                |
| `cloudyreader-preload`  | `Pipeline.__init__`                                 | Calls `detector.preload()` and ends.                                                                                |
| `entities-preload`      | `SciEntityDetector.preload`                         | Loads the NER model. `detect` waits for it.                                                                         |
| `cloudyreader-lookup-N` | `ChainResolver`                                     | Up to 16 daemon workers for one round of lookups.                                                                   |

`AfplayPlayer` starts `afplay` as a child process, not as a thread. The process plays one clip. `stop` sends terminate, waits 2 seconds, then kills. `MacosEngine` starts `say` the same way, as a child process for each reading and once at launch to list the voices.

Locks guard the shared state. `_SYNTH_LOCK` in `engines/piper.py` covers Piper, because espeak keeps process-wide state. `TtsService._lock` covers the cache. The Kokoro backend holds one lock. Each optional engine holds one lock for synthesis, and its backend holds another. `SLOT` serializes model loads. The entity detector holds two: `_start_lock` guards the model start, and `_infer_lock` serializes inference. The macOS engine holds two: one makes the voice listing run once, and one guards the running `say` processes.

## The window

`MainWindow(service, player, *, settings=None, rotator=None, parent=None)` takes every collaborator as an argument, so tests pass fakes. The file `gui/fake_service.py` holds `FakeReaderService` and `FakePlayer`. They do no synthesis, no network, and no audio. The tests set `QT_QPA_PLATFORM=offscreen`.

- **Layout.** The values live in `gui/tokens.py`, the only GUI file with raw numbers. `gui/widgets.py` draws the question card, the script panel, the focus ring, and the disclosure button of the **Spoken script**.
- **Appearance.** `gui/theme.py` maps the appearance (light or dark, standard or increased contrast) to color roles. `MainWindow` applies the roles to the custom-painted parts at start, and again when the color scheme, the contrast preference, or the palette changes. Native controls keep the system colors.
- **Voice menu.** `gui/voice_picker.py` builds the **Voice** pop-up menu and the **Speaker** box from the labels of `voice_meta.py`.
- **Status bar.** `gui/status.py` holds `StatusBar`, `ElidedLabel`, and the line glyphs of a warning and an error. The download label has three wordings, and `ElidedLabel` shows the longest one that fits.
- **About.** `gui/about.py` holds `AboutPanel`, a window with no buttons. The app menu opens it, one panel at a time.
- **Spoken script.** `gui/live_script.py` holds `LiveScript`. Each change to the question box, or to **Read answer line**, restarts a 150 ms timer. When the timer ends, one job calls `preview_script(raw, opts)` on the window's one-worker pool. A newer change makes an older job skip its work or drop its result. A blank text, or a text of more than 20,000 characters, gives an empty result, and the panel shows its placeholder. `_start` cancels the preview, and the script of the reading replaces the panel text. A service without `preview_script` leaves the panel to **Speak**.
- **Rotation.** `_start` asks the `VoiceRotator` for a voice after every guard has passed. A pick replaces the voice key and clears the speaker. An empty pool keeps the picker voice and shows a warning.
- **First use.** `_start` asks the service for `load_hint(voice_key)`. When the engine gives a hint, the window adds it to the status text of the reading, except when that status is the rotation warning. A hint that raises is logged and dropped.
- **Download.** After the first voice list, the window starts one daemon thread. The thread calls the service's `prefetch_voices(progress, cancel)`. A service without that hook gets no thread and no progress widgets.
- **Shutdown.** `closeEvent` sets the cancel event, saves the geometry, stops playback, cancels the preview, and drops the queued jobs. It hides the window, then waits for the running job, so a reading that is still in preparation never holds the window on screen. The wait happens in `closeEvent`, because deleting the pool would wait while it holds the Python GIL. The window stops playback again at `aboutToQuit`, because `afplay` outlives the app.

| An initialism spelled by letter       | `_ACRONYMS` in `formulas.py` (the only list)                                                          |
| A gene symbol without a digit         | `_KNOWN_GENES` in `entities.py` and `_GENE_SYMBOLS` in `formulas.py`                                  |
| A pause length                        | The `*_MS` constants in `normalize.py`                                                                |
| A pinned Piper voice                  | `assets.lock.json`, `PIPER_GENDERS` in `voice_meta.py` (for rotation), and `VOICES` in the `Makefile` |
| A macOS voice's gender (for rotation) | `MACOS_GENDERS` in `voice_meta.py`                                                                    |
| A macOS voice that the menu hides     | `NOVELTY` in `engines/macos.py`                                                                       |
| An engine's pinned files              | `make pin-engine ENGINE=<engine>`, which rewrites that engine's entries in `assets.lock.json`         |
| An engine's expected files            | `SPECS` in `engine_catalog.py`, then run `make pin-engine`                                            |
| Another voice engine                  | Implement `TtsEngine`, then add it to `_engines` or `_OPTIONAL_ENGINES` in `pipeline.py`              |

Run `make test` after each change.

## Preview a script without audio

The normalizer needs no voice, model, or network. This prints the words that a reading would speak:

```bash
.venv/bin/python -I - <<'PY'
from cloudyreader.models import RenderOptions
from cloudyreader.normalize import ScriptNormalizer
from cloudyreader.parser import parse

paste = "TOSS-UP\n3) CHEMISTRY Short Answer Name the compound H2O."
script = ScriptNormalizer().to_script(parse(paste), {}, RenderOptions())
print(script.text())
PY
```

The script prints:

```text
Toss-up number three. Chemistry. Short answer. Name the compound H two O.
```

`Pipeline.preview_script(raw, opts)` does the same for the window. It parses the text and normalizes it with no resolutions, so it needs no detector, resolver, voice, or network. Blank text, or text with no question, gives an empty script. A name that name detection and a lookup would change can read differently after **Speak**.

## Run the whole pipeline from Python

This needs a voice in the data folder. Run `make voices` first.

```bash
CLOUDYREADER_DATA_DIR=.data .venv/bin/python -I - <<'PY'
from cloudyreader.config import load_settings
from cloudyreader.models import RenderOptions
from cloudyreader.pipeline import build_default_service

service = build_default_service(load_settings())
voice = next(v for v in service.voices() if v.installed)
paste = "TOSS-UP\n3) CHEMISTRY Short Answer Name the compound H2O."
reading = service.prepare(paste, voice.key, RenderOptions(online_lookups=False))
print(reading.script.text())
print(reading.audio.wav_path, reading.warnings)
PY
```

The script prints the spoken words, the path of the WAV file, and the tuple of warnings. It plays no sound. Play the file with `afplay` if you want to hear it.
